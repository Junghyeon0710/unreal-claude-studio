# C++와 블루프린트 나누기

기능을 C++와 블루프린트 중 어디에 만들지 정하는 기준이다. 메인이 카드를 시작할 때(`/cards`) 이 기준으로 카드의 "C++와 블루프린트" 칸을 정한다. `ue-programmer`와 `ue-reviewer`도 이 기준을 따른다. C++ 파일을 열면 자동으로 읽힌다.

에픽 권장: C++를 기반으로 두고 그 위에 블루프린트 클래스를 만든다. 블루프린트는 동작을 정하고 빨리 고쳐 보기에 좋고, C++는 시스템을 만들기에 좋다. (에픽 문서 "Coding in Unreal Engine: Blueprint vs. C++")

## 이 스튜디오에서 C++을 기본으로 하는 이유

- 규칙과 숫자를 자동 테스트(Automation Spec, Functional Test)로 확인하기 쉽다.
- `ue-reviewer`가 글로 검토할 수 있고, Git에서 무엇이 바뀌었는지 보인다. 블루프린트 그래프는 바이너리 파일이라 Git에서 차이가 보이지 않는다.
- 메인은 C++을 직접 쓴다. 블루프린트 그래프는 `ue-editor`가 툴셋으로 노드를 하나씩 만들어야 해서 느리고 틀리기 쉽다.

## C++에 둘 것

- 게임 규칙, 상태, 판정, 계산 (예: 대시 거리, 쿨다운, 피해량 계산)
- 여러 기능이 같이 쓰는 기반 클래스와 컴포넌트
- 매 프레임 도는 것, 많이 만들어지는 것
- 네트워크 동기화 (협동 게임이면)

## 블루프린트에 둘 것

- **에셋 연결과 기본값:** C++ 클래스를 상속한 블루프린트 자식 하나(`BP_`)에서 메시, 머티리얼, 소리, 입력 에셋을 지정하고 조절 값의 기본값을 정한다.
- **겉모습 반응:** C++이 `BlueprintImplementableEvent`나 델리게이트로 "일이 일어났다"를 알리면, 이펙트, 소리, 카메라 흔들림, 애니메이션 재생은 블루프린트에서 붙인다.
- **UI 배치:** 위젯 블루프린트(`WBP_`)에서 배치한다. 위젯의 로직은 C++ 부모 위젯에 두고 `meta = (BindWidget)`으로 잇는다.
- **레벨 하나에서만 쓰는 연출과 배치**
- **버리는 시제품** (리허설, 빠른 확인용). 남기기로 하면 규칙과 판정은 C++로 옮긴다.

## 지킬 것

- 게임 규칙을 가진 블루프린트 클래스는 C++ 부모를 둔다. 블루프린트만으로 된 클래스는 겉모습, 배치, 시제품에만 쓴다.
- 에셋 경로를 C++에 박지 않는다. 블루프린트 기본값이나 데이터 에셋(`DA_`)에서 지정한다.
- 블루프린트에서 Tick을 쓰지 않는다. 타이머나 델리게이트로 일정을 잡는다(에픽 권장).
- 조절 값은 `UPROPERTY(EditDefaultsOnly)`로 노출한다. 여러 클래스가 같은 값을 쓰면 데이터 에셋에 둔다.
- 성능 때문에 블루프린트를 C++로 옮길 때는 먼저 Unreal Insights로 재고, 가장 느린 곳부터 옮긴다(에픽 권장).

## 헷갈릴 때

1. 자동 테스트로 확인해야 하는 규칙이나 숫자인가? → C++
2. 사장이 에디터에서 보면서 자주 바꿀 모양이나 값인가? → 블루프린트 기본값이나 데이터 에셋
3. 둘 다 아니면 C++에 두고, 겉모습만 블루프린트로 알린다.

그래도 애매하면 카드를 시작할 때 사장에게 추천과 함께 묻는다.
