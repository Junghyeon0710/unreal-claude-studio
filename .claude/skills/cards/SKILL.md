# 작업 카드

기능 기획서를 작업 카드로 나눈다. 카드에는 할 일, 완료 조건, 하지 않을 것만 적는다. 어떻게 만들지(구현 방법)는 카드를 시작할 때 `/work`가 정한다. 앞 카드를 만들어 보면 뒤 카드 계획이 바뀌는 일이 많아서다.

카드는 메인이 직접 쓴다. 선택 창(AskUserQuestion)은 메인 대화에서만 쓸 수 있다.

## 시작

1. 인자: `$ARGUMENTS`
   - 기능 이름이면 `docs/design/<기능>.md`를 읽는다. 없거나 상태가 `확정`이 아니면 멈추고 `/design <기능>`부터 하자고 한다.
   - 인자가 없으면 확정됐지만 카드가 없는 기획서를 추천한다.
   - 기획서 없이 할 작은 변경이나 버그면 "작은 변경과 버그"를 한다.
2. `docs/tasks/`에서 이 기획서를 가리키는 카드를 찾는다.
   - 없으면 "카드 나누기"를 한다.
   - 이미 있으면 다시 나누지 않는다. 남은 `대기` 카드는 `/work`로 진행하자고 알린다.

## 작은 변경과 버그

기획서 전체를 쓰기엔 작은 일은 기획서 없이 카드 한 장으로 한다.

- 쓰는 때: 조절 값 바꾸기, 버그 고치기, 이미 있는 기능에 작은 동작 더하기. 카드 한 장으로 끝나는 일.
- 쓰지 않는 때: 새 기능, 확정된 기획서의 규칙이 바뀌는 일, 카드가 2장 넘게 필요해 보이는 일. 이때는 `/design`부터 한다.

1. 무엇을 왜 바꾸는지 한 줄로 정리한다. 버그면 재현 순서, 기대한 결과, 실제 결과를 받는다. 모르면 묻는다.
2. 관련 기획서가 있으면 읽는다. 기획서 "조절 값"의 범위 안이면 그대로 한다. 범위를 벗어나거나 규칙이 바뀌면 멈추고 `/design`으로 기획서부터 고치자고 한다.
3. 카드를 만든다. 양식: [card-template.md](card-template.md)
   - 파일: 버그는 `docs/tasks/NNN-<기능>-fix-<이름>.md`, 작은 변경은 `docs/tasks/NNN-<기능>-<이름>.md`.
   - 기획서 칸: 관련 기획서 경로, 없으면 `없음 (작은 변경)`.
   - 할 일: 무엇을 왜 바꾸는지. 버그면 재현 순서, 기대한 결과, 실제 결과도.
   - 완료 조건: 메인이 쓴다. 버그면 "재현 순서대로 하면 기대한 결과가 나온다"를 넣는다.
4. 목록 승인 없이 바로 `/work <카드 번호>`를 이어서 한다(`work` 스킬을 부른다). 완료 조건은 `/work`가 카드를 시작할 때 카드 전체와 함께 확인받는다.

## 카드 나누기

1. 기획서의 완료 조건을 순서대로 번호를 붙여 본다(1, 2, 3...).
2. 카드로 묶는다.
   - 카드 하나는 혼자 확인할 수 있는 결과(자동 테스트나 직접 플레이)로 끝난다.
   - 나누는 기준: 검토자가 이 카드만 따로 "다시 해"라고 할 수 있는 단위. 준비 작업(폴더, 설정, 입력 에셋)은 따로 카드로 빼지 않고 그것이 필요한 카드에 넣는다.
   - 기능 하나에 보통 2~5장. 한 장으로 충분하면 한 장. 5장을 넘으면 기획서가 너무 크다고 사장에게 알린다.
   - 순서: 손으로 해 볼 수 있는 핵심 동작을 먼저, 이펙트와 소리 같은 겉모습은 뒤로.
3. 스스로 점검한다.
   - **빠짐:** 기획서 완료 조건이 모두 정확히 한 카드에 들어갔는가.
   - **범위:** 기획서 "하지 않을 것"을 맡은 카드가 없는가.
4. 승인받는다.
   - 2장 이상이면: 목록을 표로 보여 주고(카드 / 하는 것 / 맡는 완료 조건 / 확인 방법 / 먼저 끝나야 할 카드), 같은 답에서 AskUserQuestion으로 승인받는다(이대로 / 고치기).
   - 1장이면: 목록 승인을 건너뛴다. 사장은 `/work`가 카드를 시작할 때 카드 전체를 보고 한 번에 확인한다.
5. 카드 파일을 모두 만든다.
   - 파일: `docs/tasks/NNN-<기능>-<이름>.md`(영어 소문자와 `-`). NNN은 `docs/tasks/` 전체에서 다음 번호(세 자리).
   - 양식: [card-template.md](card-template.md)
   - 채우는 칸: 머리(상태 `대기`), 할 일, 완료 조건(기획서 그대로, 확인 기준까지), 하지 않을 것. "구현 방법"부터는 양식의 안내 문장을 그대로 둔다.
6. 첫 카드를 `/work <번호>`로 바로 시작할지 묻는다. 1장이면 묻지 않고 바로 `/work`를 이어서 한다.

## 지킬 것

- **기획서를 바꾸지 않는다.** 기획서와 다르게 해야 하거나 기획서가 모자라면 멈추고 사장에게 알린다. 기획서는 `/design`으로 고친다.
- **숫자는 기획서에서 그대로 가져온다.**
- **상태:** `대기 → 진행 중 → 검토 중 → 완료`. 이 스킬은 `대기`만 쓴다. 나머지는 `/work`가 바꾼다.

## 기획서가 바뀌었을 때

`/design`이 확정된 기획서를 바꿔서 영향받는 카드가 있으면:

- `대기` 카드: 할 일과 완료 조건을 다시 쓴다.
- `진행 중`이나 `완료` 카드: 바뀐 점을 "진행 기록"에 적고, 새 카드를 만들지 사장에게 묻는다.
